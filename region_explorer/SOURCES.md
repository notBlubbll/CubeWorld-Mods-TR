# Region Explorer: sources and verifiable boundaries

Verification time: 2026-10-24. Only this machine's verified 2013 Alpha is supported: `Cube.exe` SHA-256 `84A7A132A84D4282338E7EA45A1940D32066D64E39CBAFED8F2418D5A6DC30BF`.

- [RegionReveal](https://github.com/Jovinull/RegionReveal/tree/8633915f10b6ad565a31fc653d4f7e3f3b2c2484), pinned commit `8633915f10b6ad565a31fc653d4f7e3f3b2c2484`. Its `docs/MAP_LABELS.md`, `docs/REVERSE_ENGINEERING.md`, `docs/BEHAVIOUR.md`, `src/game/cube_world.hpp`, `src/game/world.cpp`, and `src/region_reveal/marks.cpp` were referenced for this version's map layout, native label categories, and quest states. The original MIT license is kept at `RegionReveal-LICENSE.txt`. This module implements its own Qube SDK read-only scan, list, target storage, and optional navigation messaging; the project's dinput8 proxy and native patch were not installed, and its region-reveal functions were never called.
- [CubeWorld-Reversal](https://github.com/qad3n/CubeWorld-Reversal): the local `external/CubeWorld-Reversal/cube/control/GameController.cpp`'s `NameGen_initFirstNameTables` (original address 0x5a0ed0) and the region-generation calls; the map serialization function in the local `cube/_library/crt_stl.cpp` (original address 0x605420). The map save structure differs from live quest data — a missing quest field in a save must not be read as "no boss".
- [Qube-Loader](https://github.com/qad3n/Qube-Loader): the project's existing SDK, ImGui, and shared loader are reused without changing the shared framework. Its GPL-3.0 license is kept with the project.
- Local read-only evidence: `research/evidence/explorer-name-layout.json` verified the 40 UTF-16 name syllables in the actual executable; `explorer-saved-records.json` verified two real maps, 761 landmarks, and 24 towns among them. The test records rebuild only the fields the save already has — no live quest states are fabricated.

WorldMap is the controller-embedded object at `gc+0x800d44`; the sparse block table is at `+0xb0`; each block's landmark area is offset 0x34000, holding 64 records of 0x68 bytes each. Town is category 1; the quest type/number is at record +0x34 and the state byte at +0x41 (0 unfinished, 1 in progress, 2 completed). Categories 0/10 take no part in native landmark labels; the 0.1.3 type verification is below, and unverified combinations still just say "landmark".

Names use the native default species-index algorithm, keeping the uint32 overflow: `(seed/7 + seed*13)%20`, `(seed*7 + seed/10)%20`. The source stores only the RVAs of the strings in this version and reads them from the user's original program at runtime — no game fonts, word lists, or map assets are distributed. No Chinese proper-name conversion was implemented.

Storage blocks are fixed-size technical chunks; the borders of named geographic regions are decided by other noise/partition rules, so a storage-block edge is not a desert or snow-region boundary. This version draws no such borders and implements no offline world prediction for arbitrary seeds.

## 0.1.2's vanilla region difficulty colors

The pinned commit's `docs/MAP_LABELS.md` was fetched over the GitHub connection; the local reference copy is at `research/upstream/RegionReveal/MAP_LABELS.md`; that document clearly separates region-name colors from quest-completion marks. The local client with the exact SHA256 was then disassembled byte by byte — no original game function was executed directly.

- The vanilla map labels at `0x4CAC69..0x4CADB3` read the region record's level at `+0x24` and the local character's at `+0x190`, calling `0x43CA60` for each.
- `0x43CA60`'s single-precision curve is `C(L)=1-1/((L-1)*0.05+1)`. The original constant `0x745DC0` is `1.0f`, `0x6FCDB4` is `0.05f`; the threshold `0x6FCB7C` is `0.1f`.
- Region curve values `<= C(player)-0.1f` stay white; above that line and `<= C(player)+0.1f` are cyan RGB `(0,1,1)`; higher are red `(1,0.2,0.2)`. The city branch stays plain white. The equality on both sides and the float evaluation order follow the original program.
- This is the region-level color using `+0x24` — never the quest-monster level `+0x3C` or the quest completion state — and it computes no equipment power. `+0x38` is the quest species field; the original note wrongly called it a level, now corrected; the color implementation always reads only `+0x24`. Distance plays no part in the color.
- This module implements this pure computation itself — it does not call or hook the native coloring function and writes no game state; it only adds one clearly-successful/failing 4-byte character-level read while the map is open; the scan frequency and range are unchanged.

The constants and layout are in `research/evidence/explorer-difficulty-native-rule.json`; the map branch and curve disassembly are in `explorer-difficulty-map-color-disassembly.txt` and `explorer-difficulty-native-curve-disassembly.txt`.

## 0.1.3's place types and the missing list entries

2026-10-25, read-only verification against the same SHA256 client. `GameController_format_region_singular @0x4E5590` actually calls `WorldMap_lookupTileValue @0x5A5240` with record `+0x18` **and `+0x1C`**, then looks up the localized `singular` template by the returned key. That queries the World's `+0x800124` red-black tree (World embedded at `gc+0x2E4`) with the two-part key — node keys at `+0x10/+0x14`, the name key being the node's `+0x18` native UTF16 string. `research/inspect_place_catalog.py` verified the exact process path, binary SHA, and module base, walking this bounded word list with VM_READ/QUERY rights only and executing no game function.

The live session read 123 keys in full, saved in `research/evidence/explorer-place-catalog-live.json`. Categories 1/2/3/4 are Village/Mountain/Forest/Lake; category 5's subtypes 0..3 are Ruins and 4 is Gravesite; 6/7/8 are Canyon/Valley/Crater; category 9 subtype 0 is Cave; 11/12/13 are Rock/Tree/Peak; 15 is Island. **Category 14's subtypes 0..5 are Castle, Ruins, Catacombs, Palace, Temple, Pyramid** — category 14 alone must not name every building the same. Ordinary terrain categories have subtypes 0..9 in the word list; with no entry, the type is not guessed. The Chinese types are direct translations of these native name keys; the proper names still come from the original game's runtime syllables. Desert/snow are another layer of biome data, not inferred from this table.

The earlier reference, RegionReveal's `src/region_reveal/marks.cpp`, indeed marks BossDefeated only when `mission!=0 && state==2`; the reference copy is at `research/upstream/RegionReveal/marks.cpp`. This live session had 6 of 489 places with a current quest (2 of them state 2), plus 4 with `mission=0,state=2` and 1 with `mission=0,state=1`. The old filter therefore listed only 6. The new filter keeps these native non-zero states and shows "retained completed/retained progress", without recognizing them as current quests, permanent history, or proof of all-boss kills; it also does not modify the game's states, icons, or quests. That session's list should be 11 with 6 completed states, 5 of them retained records with no current quest number. States can change as the game runs.

## 0.1.4's name re-check and the missing glyph

The types were re-checked against the native 123-entry word list above and the reverse-engineered `World.cpp`'s type name keys; the concrete shapes referenced the community material explicitly marked Alpha: [Giant Tree](https://cubeworld.fandom.com/wiki/Giant_Tree), [Giant Rock](https://cubeworld.fandom.com/wiki/Giant_Rock), [Missions](https://cubeworld.fandom.com/wiki/Missions). The original keys `Tree/Rock` are giant landmarks in this version, so the Chinese became "巨树/巨岩" (giant tree/giant rock). The `Crater` key says nothing about origin; "环形坑" (ring crater) is a conservative translation choice — it must not be claimed a meteor crater or volcano. `Gravesite/Peak/Catacombs` keep "墓地/山峰/地下墓穴"; no other type showed a meaning error. The community wiki mixes in 2019 content; Steam's Mana Tree and other mechanics were not adopted.

The local `cube_cn.dll` SHA256 is `F52B099FC23DB290316622DCFB211302BD5FE37E67FC141A3318737E016FD5B9`. The 40 original syllable keys' UTF-8 embedded entries were extracted read-only — all 40/40 unique and strictly decodable, with no literal `?` or U+FFFD among the 42 distinct characters. `Lugo = 露芶[IS_END]` is at byte offset 1689274 (0x19C6BA), `lon = 龙`; seed 1863 gives Lugolon, matching the existing read-only position and the screenshot's 6143 m. The original font `resource1.dat` was measured to lack "芶" U+82B6, which the Windows `msyh.ttc` can provide. The evidence is in `research/evidence/explorer-0.1.4-translation-audit.json`, including each original key, translation, code point, and offset. No proper name was freely changed to a look-alike character.

The glyph fill uses the current SDK's ImGui 1.92 dynamic font interface. The source `imgui.cpp::UpdateFontsNewFrame` locks the atlas only when the backend lacks `RendererHasTextures`; the existing `imgui_impl_dx9.cpp` supports dynamic texture updates. The module builds its own font in a supported unlocked atlas, taking the original font's data as the first source and the system font as the fallback source, selecting it temporarily while drawing the explorer and restoring after. Nothing merges into the shared default font, replaces the shared loader, or rewrites the game's word lists. The atlas holds the font resources until its own destruction; the original font data is not re-taken over, and no config-vector pointer that could dangle when adding fonts is held. With no usable backend/font, the locked atlas is not forced and the fallback is logged unavailable.

## 0.1.5's boss class basis and boundaries

The local Cube.exe SHA256 is still `84A7A132A84D4282338E7EA45A1940D32066D64E39CBAFED8F2418D5A6DC30BF`. The feasibility report is at `research/evidence/boss-class-feasibility-20261025.md`. The native spawn branches and fields come from the local CubeWorld-Reversal's `game_misc.cpp`, `control/GameController.cpp`, `world/Spawn.cpp`, and the Qube SDK's `offsets.h/creatures.cpp`; the cuwo generator was neither copied nor run, and no new dependency was introduced.

- The native `GameController.cpp` range `0x60FCFE..0x60FD4F` clearly checks quest type 5 and the Spawn's `+0x7A & 0x1000`, seeds srand with record `+0x30 + the Spawn ID's low 32 bits`, and immediately calls `0x5C7730` with that Spawn. The quest monster level is at `+0x3C` and the species at `+0x38`; both are read separately in the code and do not replace the region difficulty color.
- `0x5C7730`'s regular branch writes its first rand `%4+1` to Spawn `+0x30`; species 97 (Vampire) is forced to 4. The prediction accepts only the verified regular humanoid species with original class bytes 0..4, excluding the `flags & 0x58` early-return branch; special species, ability codes, and unknown spawn branches are not force-fit into player classes.
- Cube.exe imports the game directory's `MSVCR110.dll`, SHA256 `B30160E759115E24425B9BCDF606EF6EBCE4657487525EDE7F1AC40B90FF7E49`. Its rand (RVA 0xA492A) and srand (0xA494D) were disassembled read-only, confirming the 32-bit state `state*214013+2531011` with `(state>>16)&0x7FFF`. The module computes this round itself — it neither runs nor changes the game's RNG. The installer added a hash check for that library and does not replace it.
- The source branch sets `0x1000` and `0x200` together on a giant humanoid boss's Spawn. Both bits must be present — ordinary quest monsters, the SDK boss-species boolean alone, or nearest-distance can never be the match basis. The detailed chunks are in the World's (gc+0x2E4) `+0xBC` region grid and the Region `+0x10018` pointer table; the Spawn pointer vectors sit at Zone `+0x18/+0x1C`. The original ID is `((uint64(zoneY)<<16)+zoneX)*256+spawnIndex`, which must equal the 64-bit number at Spawn `+0x48` exactly, and the spawn position and the chunk's owning coarse landmark must also match.
- The current World's landmark records are at Region `+0x14018`; they must match the map snapshot's category, subtype, proper-name seed, quest type, quest seed, species, and level, and be unfinished. On respawn or an unreadable current quest it stays unknown — past quest seeds are never reused.
- The full Spawn ID queries the SDK's verified entity red-black tree (gc+0x2E8, node key +0x10, entity pointer +0x18) — a bounded lookup, not a whole-entity-list scan. The actual entity's kind, level, tier, and alive state must match the original Spawn, then entity `+0x140` is read. Special species show "special boss"; with several candidates, none is picked arbitrarily. The actual class beats the prediction; on a mismatch, prediction stops for this world session.

The query happens only on the Challenges page with the map open on the two-second refresh, limited to a 7×7 grid of detailed chunks nearby — at most 4096 records each, 8192 total; past the limit, no boss conclusion is output. This boundary means no class can be shown for places with no detailed spawn record — it is not a whole-world seed prediction. The original 489-record coarse map snapshot contains none of these Spawns and entities, so it cannot claim the class was ever really compared; the in-game comparison of this version is still pending.

The new binary evidence is `explorer-0.1.5-task-reseed-disassembly.txt` and `explorer-0.1.5-native-rand-disassembly.txt`; the existing `boss-class-generator-disassembly.txt` verified the regular branch. This round reopened the [official patch index](https://wollay.com/patch-notes/); it still lists 2026-10-24 v0.1.12 as latest, and the index confirms no corresponding feature reusable on the current Alpha; public searches verified no ready-made installable product, which does not assert none exists. The existing explorer-increment implementation was adopted — no version switch and no external tools installed.
